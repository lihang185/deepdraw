# 原生文件读写首版接入

本目录的 `deepdraw_fileio.dll` 已编译并通过独立测试。DLL 不链接 Python 或
引擎；引擎通过同目录的适配代码调用它。暂未替换客户端现有 pickle 读写入口。

## 离线引擎需要做的修改

1. 更新上一层的 `DeepDrawAPI.h` 和 `DeepDrawAPI.cpp`，这一轮补了保存属性读取、
   `CModelDataPublic`、实体/组件回收和装配接口，需要重新编译。
2. 引擎项目添加 `NativeSceneBridge.cpp`、`NativeSceneLoad.cpp`、
   `CModelNativeFile.cpp`。后二者不属于文件 DLL 工程。
3. CModel 声明中添加以下函数，类型定义来自 `DeepDrawFileIO.h`：

   ```cpp
   ddfile::Status SaveNativeFile(const wchar_t* path, ddfile::Error* error);
   ddfile::Status ReadNativeFile(const wchar_t* path, ddfile::Error* error);
   ```

4. 链接 `build/x64/Release/deepdraw_fileio.lib`，运行时部署同目录 DLL。
   引擎适配代码使用 C++17，Release x64 `/MD`，与 DLL 的 MSVC/STL 配置保持一致。
5. 编译检查新增 getter 与实际内部函数一致，尤其是 UV 矩阵访问；本地没有私有
   `model.h`，无法替代这一轮离线编译。

## 使用与所有权

建议在新的临时 CModel 上调用 ReadNativeFile，成功后才交给客户端替换当前模型。
文件解析、引用校验、原生实体创建完成前不修改当前文档。

适配器按已确认规则处理：未加入组件的实体单独 DeleteThis；组件使用 Release；
CModelData 容器由调用方销毁。LoadData 完成后，模型拥有实体图，适配器只销毁
CModelData 容器。LoadData 必须保证最终接管不在部分转移所有权后抛异常；若引擎
存在这种行为，需要在内部解决提交/回滚，不能由 public 包装猜测。

两个方法的实现已放在 CModelNativeFile.cpp，不必再手写文件解析代码。
保存/读取必须在没有并发编辑、撤销、模型替换的情况下执行。

## 格式范围

使用 `.dim`，但有独立的 `DeepDrawNative` 文件头和版本 1，不能交给旧 pickle
加载器。旧格式继续走现有 Python 入口；之后再做客户端按文件头分流。

首版保存基础几何、UV、组件/实例、命名集合、动态组件描述、材质和原贴图字节。
图层、曲线、辅助线、剖切面等不支持内容明确报错，不静默删除信息。现有模型文件
不会被自动转换或覆盖。新版只提高文件格式实现的隐藏程度，不属于加密格式。

## 2026-10-08 更新后的验证

新 public API 已成功链接。`tests/native_engine_fileio_test.cpp` 在不初始化 Python
的独立进程中，通过真实引擎创建三角形、保存、读取和未接管数据回收测试；另外
通过共享定义/实例、材质、原始贴图、UV、命名集合的创建和释放测试。
尚未验证 LoadData 接管后的有效性、显示对照和大场景性能。

当前 Python CModel 尚未暴露两个入口。可在既有 CModel 的 pybind11 绑定链中添加：

```cpp
.def("SaveNativeFile", [](CModel& self, const std::wstring& path) {
    ddfile::Error error;
    auto status = self.SaveNativeFile(path.c_str(), &error);
    return py::make_tuple(static_cast<int>(status), std::wstring(error.message));
})
.def("ReadNativeFile", [](CModel& self, const std::wstring& path) {
    ddfile::Error error;
    auto status = self.ReadNativeFile(path.c_str(), &error);
    return py::make_tuple(static_cast<int>(status), std::wstring(error.message));
})
```

返回 `(0, "")` 表示成功，其余返回值由客户端作为失败处理。Python 只调用入口，
文件解析、遍历、创建和装配仍在 C++ 完成。读取应针对新建的临时模型，成功后
再走既有文档替换流程，不直接覆盖正在编辑的模型。

也可包含 `NativeFileBindings.h`，在 CModel 的 `py::class_` 变量注册完其他方法后
调用 `ddfile::BindNativeFileIO(model_class)`。删除原先直接绑定成员函数的两个
`.def`；不能只绑定 `&CModel::ReadNativeFile`，否则未注册的 Error/Status 类型
会暴露给 Python，无法调用。辅助函数不需要注册这两个内部类型。

运行时 `deepdraw_fileio.dll` 必须与 `editor2.cp38-win_amd64.pyd` 一起部署到
`engine/native/cp38/`，否则 engine 导入时会出现找不到 DLL 的错误。

## Python 入口与模型接管验证

LoadData 接管、TestValidity、共享定义、中文命名集合、材质和镜像非均匀缩放

runtime/native-fileio-kowloon/native.dim。
